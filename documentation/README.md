# Documentation portal

Astro Starlight is the owner-approved technology for this independent static
documentation artefact. Implementation and deployment still require owner review.
Repository Markdown remains authoritative; edit the source shown on each
page. [Documentation ownership](../docs/README.md) and the
[diagram catalogue](../docs/architecture/diagrams/README.md) retain their responsibilities.

## Local workflow

Use the repository Node.js/npm baseline, Docker Engine, and the Playwright Chromium
browser. From this directory:

```bash
npm ci --ignore-scripts
npx playwright install --with-deps chromium
npm run dev
```

Open the loopback URL printed by Astro. Canonical Markdown, Mermaid and DSL edits
regenerate derived content and reload the browser. Pagefind search is generated by
the production build; use preview for search validation.

```bash
npm run build
npm run preview
npm run validate
```

`npm run check:reproducibility` optionally compares two cold builds byte for byte,
including freshly rendered diagrams; it clears only the derived diagram cache.

The build uses the catalogue's pinned Mermaid CLI and a digest-pinned official
Structurizr export container plus a pinned PlantUML renderer. The official C4-PlantUML
export is disposable: it supplies every relationship from the DSL, and PlantUML
routes the connectors using its bundled Graphviz and C4 library with networking
disabled. First use downloads the containers; subsequent builds cache outputs keyed
by source and renderer configuration. Deleting `.cache` forces regeneration.
No diagram service, CDN or external search runs in the served site. CLI telemetry
is disabled by the npm scripts.

## Content and maintenance

`content-map.mjs` curates reader journeys. Tracked Markdown under `docs/`, plus the
explicitly selected orientation/operator READMEs, is transformed into ignored
`src/content/docs/`. Titles come from existing headings; links to included pages and
reviewed attachments resolve locally. Links to executable files remain GitHub links.
Only tracked, allowlisted attachments are copied; ignored files, environment files, generated
API HTML and arbitrary repository trees are excluded. Research is marked historical,
and ADR status comes from its source. Source status remains authoritative for sections.

`npm run build` checks published pages, heading fragments, image references, diagram
artifacts and local search output. `npm test` checks transformation boundaries;
`npm run test:browser` checks navigation, search, theme switching and diagram controls.
`bash scripts/test-container.sh --browser` exercises those journeys under the production
server and its security headers.
`npm run review:diagrams` captures native-size exports into ignored `.cache/visual-review/`.
Browser screenshots in ignored `test-results/` support visual inspection; automated success
alone does not establish diagram fidelity. Keep the existing repository documentation
validator as well:

```bash
bash ../scripts/validate-docs.sh
```

## Private serving

Deployment sources live under `documentation/deploy/`, outside the application
promotion fingerprint; portal updates do not require application runtime acknowledgement.
The private-dev operator guide remains the single owner of host commands.

The production output is `dist/`; any static server can serve it. The non-root
container copies only this output and serves actual files with 404 responses for
unknown paths. Private-dev installation, access policy, host acceptance and isolated
rollback belong to the [operator guide](../deploy/private-dev/README.md#documentation-portal).
No live deployment or public publication is authorized by building the portal.

## Dependency and image maintenance

The lockfile fixes the complete npm graph. `package.json` carries two transitive
security overrides; remove them only after upstream constraints admit patched
versions and the audit/render checks still pass. Build-time licence inventory and
notices are generated into `.cache/licenses.json` and `public/third-party-notices.txt`.
The static site includes the notices. Astro/Starlight and Mermaid are MIT; the
Structurizr export command is free/open source (its licensed server mode is unused),
PlantUML is GPL tooling (generated diagrams retain the model owner's rights),
and the Nginx image carries its upstream notices. LGPL libvips and EPL ELK are
build-only tooling, absent from the static runtime. Preserve upstream licences when
redistributing tooling. Optional dependencies differ by build platform; the supported
container target remains AMD64.

Run `npm audit --audit-level=high` and the repository-pinned image vulnerability
scanner when dependencies/images change. Build/search/browser checks cover the
security overrides. The runtime copies only `dist`, has no npm/Java/Chromium or source
tree, and does not embed secrets. Its CSP allows Starlight's inline initialization
and local Pagefind WebAssembly; remote script/style/font/search origins are denied.
The existing generated Redoc HTML retains its GitHub link because it uses a runtime
CDN; the canonical OpenAPI download and API guidance remain available locally.

This portal starts as its own initial pre-1.0 `0.1.0` artefact. It does not change the
backend, frontend or OpenAPI versions. Follow the
[delivery lifecycle](../docs/development/delivery-lifecycle.md#semantic-versioning)
for subsequent changes and publication approval.
